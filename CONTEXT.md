# CONTEXT.md — канонический контекст Omega VPN

**Дата фиксации:** 2026-10-08. **Текущий уровень готовности:** feasibility подтверждён частично, приложение не разработано. При расхождении статусов верить коду и проверкам, а не плановым датам.

## 1. Зачем проект

Пользователю нужен личный **бесплатный** Android VPN-клиент с опытом «одна кнопка + доступные страны/узлы», вдохновлённый Happ. В качестве возможных провайдеров назывались Capybara VPN и Panther. Ключевое условие: работающий интернет **без оплаты, обязательной карты, платного API и своего VPS**. Одновременно недопустимо обходить платные подписки Capybara/Panther: их ключи можно импортировать лишь при наличии законного доступа.

Устройство первой приёмки: **OnePlus Nord 3, Android 15**, мобильный интернет и Wi-Fi. Основной репозиторий: [xxiamadelxx-blip/omega-vpn](https://github.com/xxiamadelxx-blip/omega-vpn), ветка `main`. Первое состояние репозитория было пустым.

- APK SHA-256: `488923701e7d46e556b8566e50f03ef1b13ad807be0299feb892b83a2242a093`. Проверен по digest GitHub Release. Package: `su.happ.proxyutility`, версия `4.7.1`.

- Манифест: `su.happ.proxyutility.service.XRayVpnService` с `android.permission.BIND_VPN_SERVICE`; также `XRayProxyOnlyService`, `XRayAntiFilterService`, `XRayTestService`.

- Весь код, графические ресурсы и брендинг Happ остаются собственностью правообладателей. Реверс нужен для понимания схемы, **не для копирования**.

## 3. Архитектурные решения (ADR)

| ID | Статус | Решение | Почему |
| --- | --- | --- | --- |
| ADR-001 | ПРИНЯТО | Android-first, только личный MVP | Максимальный шанс измеримого результата |
| ADR-002 | ПРИНЯТО | Нет обязательного backend, платных API, своего VPS | Условие бесплатности; минимальная стоимость и поверхность атаки |
| ADR-003 | ПРИНЯТО | Первый протокол VLESS + TLS/REALITY | Есть проверенное тестовое подключение; меньше объём работ |
| ADR-004 | ПРИНЯТО | Нельзя копировать декомпилированный Happ | Законность, лицензии, поддерживаемость |
| ADR-005 | НА ПРОВЕРКЕ M1 | База: v2rayNG/Xray (fork/реиспользование) или Android sing-box | Выбирать по лицензии, build-spike и реальной TUN-работе |
| ADR-006 | ПРИНЯТО | Подписки поставщиков по стандартным ссылкам и только с правом доступа | Без обхода платежей, авторизации, пробных сроков |
| ADR-007 | ПРИНЯТО | Публичные источники не считаются доверенными | Валидация, предупреждения, не хранить секреты в Git |
| ADR-008 | ПРИНЯТО | Без теста Android + Wi-Fi + mobile нельзя принять MVP | Облачный HTTP 200 доказывает только осуществимость |

## 4. Что считаем MVP / не-MVP

**В MVP:** устанавливаемый APK, запрос системного разрешения VPN, импорт/обновление открытых подписок, валидация VLESS/Reality, выбор узла и подключение/отключение, состояние/ошибки, доказательства смены IP и работа HTTPS, DNS/IPv6-тест, ограниченный fallback, Wi-Fi + мобильная сеть, 30 минут без потери туннеля, отсутствие платной зависимости.

**После MVP (только по результатам нужности):** каталог стран с флагами, геолокация и рейтинги узлов, удобный поиск, расширенная маршрутизация по приложениям, Hysteria2/Trojan/VMess, полноценная автоподборка, облачная синхронизация, сложный дизайн, автоматические рекомендации, встроенное сопоставление брендов VPN. Не обещать «анонимность», «полную безопасность» и «всегда бесплатно».

## 6. Инженерные ориентиры

Рабочая декомпозиция: **UI → subscription parser/validator → endpoint selection → Android VpnService → open-source Xray/sing-box core → internet**. Для диагностики создаётся отдельный верифицируемый отчёт, не содержащий URL с секретами. Прежде чем писать UI и собирать страны, собрать вертикальный срез VPN.

При выборе форка исследовать v2rayNG и GPL-3.0; правила распространения и лицензии пересматриваются по **точному зафиксированному коммиту**. При выборе sing-box проверить Android SDK/binding, архитектуры ARM, лицензии и работу без отдельного сервера.
